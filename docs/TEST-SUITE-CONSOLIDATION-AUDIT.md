# Test-Suite Consolidation Audit

## Scope And Verdict

The bounded expensive non-Reports workflow audit is complete. It challenges
whether a check needs to exist, which owner should hold it, and whether its
setup or waiting proves anything. It is not a claim that every test in the
repository is minimal. Reports-specific consolidation belongs to its rebuild.
No production behavior, coach data, release budget or acceptance threshold changes.

## Deliberate Limits

- Integrity's seeded stateful operation campaigns are not redundant with isolated
  deterministic examples. Seeds, operation counts and assertions are unchanged.
- Copy-standard and real-data traversal include Reports. They remain with the
  Reports rebuild, not partially rewritten here.
- Real media generation, intentional slow I/O, animations and native/browser
  boundaries are not removed merely because they consume time.
- No new framework or harness replaces the retired one. Completion guards can
  add code; their benefit is avoiding unconditional delay and rejecting missing
  work, not a claim that fewer lines alone proves better coverage.
- Passing runs are supplemented by retained-predicate comparisons and injected
  faults. Synthetic predicate checks are distinguished from full-harness runs.
- Focused receipts do not establish full-gate runtime or installed approval.
  The next full gate requires coach authorization; the six-minute target remains
  report-only during consolidation.
